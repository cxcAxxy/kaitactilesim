# 摸牌：共享配置与示例导出

摸牌的 `tasks/poker_draw/scene.xml` 直接包含 `shared/mjcf/robot.xml`，
机器人/双手外观、主桌、背景和相机沿用 shared；任务 config 直接导入
`shared/posture.py::ARM_HOME`。不要在摸牌目录复制一套相机或初始姿势。
加宽矮桌的几何尺寸、扑克牌及任务接触参数仍由摸牌任务管理；矮桌表面引用
任务自己的浅灰石纹，与 shared 深灰主桌保持同一材质风格但有明确亮度区分。
扑克牌背面使用任务自己的红色/暖金菱形格纹理。这两项都只改变视觉外观，
不改变桌牌摩擦、碰撞、观测或动作接口。

当前紧凑示例目录为 `datasets/poker_draw_example/`，布局与
`datasets/usb_insert_example/` 一致：仅保留 `raw/`、`review/` 和
`curves/`。新版从共享收臂初态开始，由执行器连续接近牌，不把 reset 状态
直接设在牌上方。

## 连续动作版本

`right-side-low-chatter-v4` 将初始双臂配置保持不变，只调整摸牌执行器轨迹和
摸牌任务专属的柔顺接触阻尼：

- 起始手指和右臂目标按同一最小急动度曲线逐物理步更新，小指不再突然追逐整段弯曲目标。
- 起步不再在关节空间插值并绕到身体中线；改为右侧笛卡尔轨迹，向右外侧
  最多避让 55 mm、同时抬高 35 mm，再自然到达牌上方。实际末端横向范围为
  `y=-0.228～-0.164 m`，始终留在右臂工作区。回归测试同时检查双手间距。
- 到牌上方后只下降，去掉原先接近过程中的再次抬高手臂。
- 中档拖牌速度由 6 改为 12 mm/s；压力建立阶段使用单独的有界增益/速度，
  建立完成后恢复原拖动反馈。每指 0.5 N 目标、桌牌摩擦和 4 N 水平限力不变。
- 夹牌采用同侧腕关节解：轻抬、拇指从露出桌沿的牌正面托起并与四指对夹，
  不再切换到另一侧腕姿绕行约 300°。牌保持自由刚体，允许真实接触使其倾斜。
- 拇指接牌最后两关节的接近时间由 0.20/0.24 s 改为 0.40/0.80 s，
  逐物理步更新；Cartesian IK 的 20 ms 分段目标也连续插值到物理步。
- 接触短暂减弱时暂停路径并保持原关节目标，不用受力偏移后的实测关节值
  反复重设目标，避免消除伺服预载、产生新的腕部指令跳变。
- 桌牌与牌/指腹两类柔顺接触的阻尼比由 1.0 提高到 1.5，同时把接触时间常数
  从 10 ms 按比例调整为 6.67 ms，使等效刚度和静态压入量近似不变。该参数
  在整条 episode 内固定，不改变摩擦系数，也不对保存的触觉信号做滤波。
- 拇指形成双面支撑后额外稳定 0.45 s；离桌的 4 mm 转移和后续 21 mm 抬升
  分别使用 0.65 s、1.25 s 的最小急动度轨迹，降低刚离桌时的加速度冲击。
- 看牌依据实际夹持后的牌/手相对位姿求目标，再连续移动与旋转手臂；
  抬臂时就配合内转，随后转成竖牌。牌局部 Y 是 88 mm 长轴，X 是 63 mm
  窄边；长轴朝竖直、窄边在下，牌正面朝向机器人，不再横着看。
  选择肘部较低的竖牌逆解分支，并检查末端肘部不高于肩部 40 mm，避免抬肘遮头。

普通 `pixi run view -- --task poker-draw` 仍是基础场景（拖牌目标每指 0.35 N）；
中档正式采集仍是已有柔顺接触预设（拖牌目标每指 0.5 N）。两者现在共用
有界法向力夹持反馈和短腕路径：基础场景的夹牌目标是每指 0.75 N、拇指 3 N，
柔顺采集预设的夹牌目标维持每指 0.25 N、拇指 1 N。这些是控制目标，不保证
瞬时测量值严格相等。没有更改基础场景的碰撞、摩擦或机器人的关节限制。
基础场景的夹持积分增益为 0.035；柔顺采集预设的夹持积分增益由 0.10 降为
0.06，最大关节修正速度由 1.5 降为 1.0 deg/s，最大修正范围由 1.0 降为
0.75 deg。这样仍允许触觉闭环维持双面支撑，但不再追逐每个瞬时求解器尖峰。
原始触觉数据未滤波，拖牌阶段的压力参数均未因此改变。

成功门槛、触觉计算、Raw 时钟/schema、相机和关节映射均未放宽或更改。
轨迹速度和夹持过渡分布有所改变，不保证历史模型的成功率保持不变。

## 重新生成一条独立示例

采集沿用[统一采集](../workflows/data_collection.md)的 `poker-draw` 入口，
先选择一个**尚未存在**的新批次目录，不向旧批次混写。
取得成功 Raw 后，下面的离线导出入口使用单线程软件渲染：

```bash
pixi run export-poker-example -- \
  /path/to/successful/episode_000000_card_right.h5 \
  --output-dir /new/path/poker_example
```

导出器只接受校验通过的成功 Raw 数据，不执行新的物理任务，不修改原始数据，
遇到已有 `review/` 或 `curves/` 会拒绝覆盖。

## 四类产物

1. `raw/*.h5` 与同名 JSON：原始 `head`＋`right_wrist` RGB、状态、动作、
   触觉、时钟、相机标定及 outcome。
2. `review/review.mp4`：顶部＋右腕原始图像，右手五指法向/切向热图。
   展示采样为 10 fps，不降低原始 30 Hz 相机数据；上排触觉为法向，下排为切向。
3. `review/robot_global_short_path.mp4`：同一次保存的 qpos 的全局视角
   **运动学回放**。使用最邻近已保存状态，不插值、不调用物理步进，
   不是训练相机输入。
4. `curves/right_hand_force_curves.png`：右手五指原始 Fn 和 |Ft|。
   Fn 为每指 taxel 法向之和；Ft 为有符号局部切向 X/Y 分量分别求和后的向量模，
   不是世界坐标 XY，也不是逐 taxel 模长相加。曲线不额外滤波。

共享外观/初态变化可能改变图像和轨迹分布；格式兼容不代表旧模型表现不变。
导出器检查当前 MJCF 指纹与 Raw 一致；模型指纹不涵盖独立网格/纹理内容，
跨版本回放还需保留采集时的运行资产。外部模型闭环性能应另外测试。
