# 共享双臂初始姿势

七个任务使用同一份 `shared/posture.py::ARM_HOME`。左臂保留已经确认的自然屈肘、小臂近乎水平的姿势；右臂按机器人关节轴约定镜像。

| 手臂 | Joint 1–7，单位：度 |
|---|---|
| 左臂 | `112, -75, -80, -120, 150, 0, 0` |
| 右臂 | `-112, -75, 80, -120, -150, 0, 0` |

两个上臂靠近身体，肘部夹角约 67°，小臂相对桌面约 2°。共享配置只读；各任务的 `config.ARM_HOME` 和旧 `workcell` 导入入口继续作为别名，避免维护多份数值。

`ArmHandSimulation` 的构造和重置都从该配置设置关节状态、目标和内部命令。两只手使用共享仿真核心中的同一套放松张手姿势。白板和花瓶不再在 reset 中把右手直接放到工具上方；录像开始后，通过执行器连续移动至任务接近点。

抓取 IK 的参考姿态属于任务标定，不是初始姿势。抓放、卡片、内存等任务显式保留各自的 IK 分支和抓取方向，以免改变 idle 姿势后错误地重定义抓取姿态。任务运动中可以使用这些接近点，但不能在 reset 中覆盖 shared home。

USB 接近前的悬停时间统一为 2.1 s，给折叠初态的腕部转动留出跟踪时间；卡片首先用 3 s 平滑进入净空路点。抓放在 ready 路点稳定后继续接近，白板和花瓶各新增 3 s 的实际接近过程。灯泡旧双指模式先在收臂状态转腕，再进入其标定分支；五指模式保持原有抓取流程。

## 对下游的影响

- 关节/执行器映射、观测和动作维度、相机内参与安装参数、触觉参数和数据格式保持不变。
- 新初始姿势会改变腕部相机的初始世界位姿和初始画面，也会改变接近轨迹、任务时长和接触历史。采集继续保存真实相机外参与时间戳。
- 内存的全程 `minimum_palm_down_cosine`、卡片的 `maximum_palm_normal_z` 仍包含初始收臂和转掌阶段，不能再假设整个过程都掌心向下。任务的掌心方向检查作用于相应工作阶段；原有触觉、插入及保留物体的判定仍然生效。
- 旧录制保留其已保存的初始 qpos；回放不会把历史轨迹改成新初始姿势。旧示例与新录制分别保留。
- 接口回归和自动任务执行不能替代历史 checkpoint 的完整闭环评估；新初始画面和接近动作可能影响已有模型表现。

`tests/test_shared_home.py` 对七个实际任务的构造和重置检查共享初始姿势、左右肩肘腕镜像、锐角屈肘和近水平小臂。

白板示例的 [预览页](../datasets/erase_whiteboard_example/index.html) 提供双臂初始姿势总览和从该姿势开始的完整任务回放。
